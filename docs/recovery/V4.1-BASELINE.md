# Version 4.1 recovery baseline

The historical comparator is final pre-V5 main, **Version 4.1.0, schema 18, family `ink-morrow-4`**. Archive tag: `archive/v4.1-pre-v5`. Commit: `74741f7d4f6b7a29f7e3d19d795ab0dd252700cc` (3 September 2026).

The target application remains Version 5.0.0, schema 23, family `ink-morrow-5`, at the catalogue-studio integration baseline documented in the implementation guide. These are different durable data families. The archive tag preserves a source reference, not a deployment, certified release or database conversion mechanism.

The original `release/4.0.0` and `v4.0.0-beta.1` are earlier historical records. The final V4 snapshot includes the later 4.1 Scribes, optional scenes, Play sessions, campaign state, alternate paths/prose shaping, deterministic solo tools and feedback fixes. Those features must be considered in recovery even though several original feature branches were already gone before cleanup.

## Comparative acceptance tasks

1. Begin an ensemble story without an obligatory avatar; set supporting/background depth and distinguish Scribe persona from cast, model and speech voice.
2. Return to a long work, inspect Chronicle/Codex, follow a source and return to the same passage without losing draft or focus.
3. Plan an empty scene, later group existing passages, and change craft for future narration without rewriting old events.
4. Inspect a promise, debt, secret, relationship, faction/resource and deadline; identify visibility, source, correction/retirement and retained history. Record any deliberately deferred type rather than hiding it.
5. Inhabit and release control; distinguish Ask, action intention, actual speech and narrated outcome. A failed/interrupted action must not manufacture a promise or fact.
6. Explore an alternate path and retain the original future; evidence and remembered knowledge must follow only the selected ancestry.
7. Upload art, inspect unplaced art, listen to cached audio, build a book and make a private all-path save with clear scope and no surprise purchase.
8. When B9 is included, draw from a deck and update a clock; replay/fork/import must preserve the correct historical outcome without re-rolling or using AI.

Use archived source, fixtures and existing imagery to establish historical intent. Record a task as observed only when actually exercised on a named build/device. Current V5 mechanical tests, prototype review, real-tablet review and live narrative evaluation remain separate evidence classes. No old server was started and no paid calls were made for this baseline revision.

## Decision boundaries

- Restoring creative tools does not enable the legacy runtime, automatic prepared successors, boot-time image backfill or a second transcript authority.
- Copyediting is still D1-gated; V4.1 manual writing is not authorization to reinstate it in V5.
- Old V4.1 database/archive conversion remains D2 and must preview unsupported content before copying; no in-place family adoption.
- B9 is explicitly deferred beyond the core B0–B8 qualification. Its omission from a core release must be stated.
- The archive reference is permanent historical context. Start implementation from current main after checking for newer changes, not from this archive or a deleted branch.
