# Art assets and safe upload

Ink Morrow 4.0 stores illustrations separately from manuscript pages. An
`asset` owns one normalized image and an `asset_placement` positions it before
the first prose page or after a stable page ID. Moving, unplacing, or deleting
art never renumbers prose, changes page revisions, invalidates a prepared next
page, or contributes continuity evidence.

## Sources and provider boundary

Assets have either an `uploaded` or `ai-generated` source. An upload is local:
it makes no AI request, costs zero, and applies no semantic classification or
subject moderation. The image is never sent to a provider merely because it
was uploaded or placed.

Provider-reference permission is an explicit per-asset boolean. Provider code
must name asset IDs and the store resolves only ready assets whose permission
is currently enabled. Archive import resets that permission to false, so
consent cannot silently move to another installation or imported copy.

## Technical upload boundary

`POST /api/stories/:id/assets/upload` accepts one multipart field named
`image`. The request is streamed to a private staging file with bounded file,
field, and part counts. The current limits are 20 MB encoded input, 40 million
decoded pixels, and a 4096-pixel maximum display dimension.

Accepted inputs are JPEG, PNG, WebP, GIF, and AVIF when the installed decoder
supports them. The server:

- matches the declared media type to the file signature;
- requires the image container to end exactly, rejecting trailing/polyglot data;
- rejects active SVG rather than serving it;
- decodes within the pixel limit and fails closed on decoder warnings;
- applies orientation, flattens animation, and writes a new WebP derivative;
- strips EXIF, XMP, IPTC, and ICC metadata;
- assigns random storage names unrelated to the uploaded filename; and
- removes partial staging, failed rows, and orphan files after interruption.

Only the normalized derivative is retained and served. Content responses use
private, no-store caching and a sandboxed content policy.

## Placement and lifecycle

Placements use `(story_id, after_page_id, ordinal)`. `after_page_id = null`
means before the first page. Ordinals are contiguous within each anchor, and
database triggers require the asset and anchor page to belong to the same
story. Deleting or truncating an anchor removes its placement through foreign
keys while the asset remains available for later placement. Deleting an asset
removes all of its placements and derivative; deleting a story removes all of
its art.

The compatibility scene-painting endpoint still accepts generated bytes at
`POST /api/stories/:id/pages/:number/image-page`, but its 4.0 semantics create
an AI-generated asset placed after that stable prose page, or Gallery-only
when `gallery_only` is true. It retains the visible prompt, provider identity,
and resolved reference IDs as provenance. It never creates an image page.

## Archive and publication behavior

Same-version `.inkmorrow` archives include ready art metadata, placement
anchors, and normalized files when visuals are selected. Storage keys and
provider-reference consent never travel. Copy import remaps story, page,
asset, and placement IDs; media receives a fresh random storage key.

EPUB export embeds placed art in the XHTML document of its prose anchor. Art
does not add a navigation/spine page or alter the manuscript page count.

## API summary

| Method | Route | Purpose |
|---|---|---|
| GET | `/api/stories/:id/assets` | List assets and placements |
| GET | `/api/stories/:id/assets/anchors` | List bounded stable placement anchors without prose |
| POST | `/api/stories/:id/assets/upload` | Stream, validate, normalize, optionally place |
| PATCH | `/api/stories/:id/assets/:assetId` | Edit title/alt text or explicit reference permission |
| DELETE | `/api/stories/:id/assets/:assetId` | Delete derivative and placements |
| GET | `/api/stories/:id/assets/:assetId/content` | Serve/download the normalized derivative |
| POST | `/api/stories/:id/assets/:assetId/placements` | Add a placement |
| PATCH | `/api/stories/:id/placements/:placementId` | Move a placement |
| DELETE | `/api/stories/:id/placements/:placementId` | Unplace without deleting the asset |
