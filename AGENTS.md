# Project memory

Persistent notes for this project (ScribeTribe, ~/src/scribe-tribe).

## Project overview

- Gothic interactive-fiction writing tool: Express backend (node:sqlite, no native builds) serves the API and the static vanilla-JS frontend on :3000
- AI via OpenRouter (key in backend/.env, see backend/.env.example); branding per ScribeTribe-OpenCode-Branding/ in the repo root (frontend assets in frontend/brand/, WebP + SVG only — PNG masters stay in the package dir)
- Dev server control: `~/bin/st-server {start|stop|restart|status}` (PID-file based) — never `pkill -f` a pattern; a command line containing the plain string anywhere in its argv self-matches and kills the shell (hung the tool twice). Use the helper.

## Testing

- Lint: `npm run lint` at the repo root (ESLint 9 flat config in eslint.config.js, installed at the ROOT, invoked via `node node_modules/eslint/bin/eslint.js` — never .bin shebangs on Termux). Config: backend = node/commonjs, frontend/app/** = ESM browser+node dual-world, frontend/tests = ESM + jest globals, e2e/tests = ESM + browser globals (page.evaluate callbacks run in the page). no-unused-vars is tuned (args/caughtErrors none) — express signatures and commented catches are the house style. `npm test` runs lint first; CI has a dedicated lint job gating the Jest job.
- Reply quality guards (backend/src/quality.js, wired into ai.js chatCompletion via `quality` opt): providers happily "succeed" with empty, clearly-truncated, or wrong-language text. checkReply = 'empty' (whitespace/prose-less; terse-but-finished is NOT this) | 'truncated' (prose, after stripping the <<<CHARACTER_STATE>>> block, doesn't end in [.!?…"'”’)] — em-dash/hyphen endings count as cuts — or below minWords) | 'language' (ENGLISH_STOPWORDS ratio: only fires when the user's own material (last user message) is confidently English (ratio ≥ 0.15) AND the reply is confidently not (< 0.02, or < 0.05 with ≥ 30% foreign-script letters) — a user writing French is never second-guessed; tokens must be /\p{L}'+/ Unicode or 'forêt' splinters into 'for' and poisons the ratio — LIVE-VERIFIED BUG). Bad replies retry (a language slip first appends a 'reply in English only' system message once); if the last attempt still fails → 502 with an honest message, NOTHING is saved (garbage never enters story_pages). pageQuality(wordTarget): minWords = quarter of the EXPLICIT words target (floor 15) — target-less (legacy) requests skip the floor (mocked tests & old clients send terse pages; truncation-shape/language still apply). quality: {minWords:30} on image-prompt condense, {minWords:20} on moderation rewrites; drafts are exempt (their strict-JSON parse failure is its own graceful retry path)
- Backend: `cd backend && node node_modules/jest/bin/jest.js` (jest via direct node — npm .bin shebangs fail on Termux)
- Frontend: `cd frontend && node --experimental-vm-modules node_modules/jest/bin/jest.js` (native ESM suite; plain `npm test` also works — the flag lives in the npm script). Tests import `jest` from '@jest/globals' explicitly (ESM Jest does not inject the global into imported modules) and load fresh app boots via `loadScript()` in tests/dom-helpers.js, which cache-busts the bootstrap with a query string (`import('../app/bootstrap.js?run=N')`). Each boot marks a liveness token (`window.__stLiveBoot`); routers of superseded boots are dead. Shared jsdom quieting in tests/setup.js stubs HTMLMediaElement play/pause/load + window.confirm.
- E2E (Playwright): `cd e2e && node sweep-e2e-server.cjs && node node_modules/@playwright/test/cli.js test --project=chromium` then sweep again + `--project="Mobile Chrome"` — each project in its OWN invocation (one webServer spans a single invocation; sharing it leaks data between projects as duplicates); sweep before every invocation to clear orphans of aborted runs (the e2e npm test chain does this for you)

### E2E on Termux quirks

- playwright-core must be patched for `process.platform === "android"`: three `Unsupported platform: android` throw sites in node_modules/playwright-core/lib/coreBundle.js → treat android like linux (re-patch after npm install)
- Use system chromium via executablePath /data/data/com.termux/files/usr/bin/chromium-browser (`pkg install x11-repo chromium`); never `npx playwright` (.bin shebangs)
- An ABORTED e2e run (Ctrl-C, tool timeout) orphans its webServer (`node server.js`), which blocks the next invocation's port or serves stale data. Run `node sweep-e2e-server.cjs` before each project invocation (the e2e npm scripts do this automatically); the sweeper matches bare-argv `server.js` + NODE_ENV=e2e only — the dev server's full-path argv can never match. Playwright port-checks BEFORE any hook runs, so no in-playwright fix is possible; the orphan must be swept pre-CLI
- Suite speed is NOT a bug: ~3.5s per-test floor (browser context spawn on this tablet) × 26 chromium tests ≈ 2m; the responsive viewport matrix runs in the chromium project ONLY (its contexts cover phone/tablet sizes; the npm test chain sweeps between projects). Mobile Chrome project: 18 tests ≈ 1m40s. When piping runs through `tail`, output is invisible until the phase ends — a running phase looks like a hang; prefer unpiped or grep-based output
- Isolation: e2e runs on port 3100, reuseExistingServer:false, env inlined in the webServer command (DB_PATH=":memory:" PORT="3100" …) — verified it creates nothing in database/scribe-tribe.db. Never point e2e at 3000; the dev server there uses the real DB. If a leak is ever suspected, fixture names to hunt: 'Context Realm', 'Sir Context', 'Generation/Retry/Error/Export/Burn Test'

## Architecture notes

- Stories carry a tiered cast as [{id, role, relation, state}] in stories.characters: role mc|supporting|background (one MC MAX, server-enforced; MC is OPTIONAL since 2026-08-30 — zero MC = ensemble tale, the creation form and cast editor both allow it and explain: with a MC the scribe keeps their voice/goals/perception central, without one she follows the directions wherever they point), relation = free-text tie to the MC at story start; state = per-story mutable instance (personality/appearance/relationship_to_mc) that the model updates via a <<<CHARACTER_STATE>>> JSON block appended after each generated page (split off before storing; malformed blocks degrade gracefully). Legacy plain-id casts are REJECTED (data was wiped 2026-08-29). Frontend (app/features/library/story-editor.js): creation declares an EXPLICIT cast shape (Centered on a lead / Ensemble — #castModeCentered/Ensemble radio buttons; lead picker reveals only in centered mode; relation label reads "Tie to {lead}" when one exists, "Starting connection or story note" otherwise); CAST EDITOR (☰ Cast on story cards, #storyCastModal, ROSTER/DETAILS layout): fetches fresh GET /:id, roster lists members with role pills + cross-world provenance + story-changed markers, detail pane edits the selected member (role select, starting connection, in-story state fields AS-IS with base-sheet placeholders; direct Make lead / Switch to ensemble actions; empty cast can add a Lead directly via the add-row role select, option disabled when a lead exists), add/remove live, saves via PUT /:id {characters} (server preserves state exactly; the client sends complete entries). Dirty drafts guard Cancel/Escape/backdrop (dialogs.confirmDestructive); role changes preserve focus + local edits (focus restored by control index after pane rebuild)
- Per-page AI accounting: model, prompt/completion tokens, cost_usd on story_pages; stories expose total_cost_usd; frontend settings (localStorage st-settings): model picker (GET /api/models proxy, entries flagged `reasoning` show a low/medium/high reasoning-effort select sent as `reasoning_effort` on generate/regenerate/preview), words per page (50–2000, scales max_tokens), story font + text size, scriptorium writing background, cost ticker (default on), narration model/voice pickers with ≈per-page cost labels
- Speculative next-page previews live in the story_previews TABLE (not memory — they must survive server restarts because the browser's green "Next Page" does; single-use, stale-checked against page count, invalidated by every live write). expected_page is snapshotted BEFORE the slow generation (post-await computation let raced previews store wrong expected numbers / wrong-context prose). Frontend gives each speculative attempt a TOKEN: live writes (direction generate, retry, burn, failed commit) discard + bump it, so a stale in-flight preview response can never turn the button green — that bug masqueraded as "green button regenerates instead of committing" (silent 404-fallback double-billed the slot). A direction-generate always discards first so a FRESH preview fires after it
- AI drafts: POST /api/ai/world + /api/ai/character (seeds → short/medium/long JSON drafts, variant counter for regenerate)
- Old pages are read-only; writing happens on the last page; "delete everything after this page" truncates via DELETE /api/stories/:id/pages?after=N with the shared destructive dialog (app/core/dialogs.js confirmDestructive: exact count + range + consequence, price-free)
- Export is EPUB (dependency-free zip writer in backend/src/epub.js); image pages embed as book plates (OEBPS/images/, alt text from image_prompt); a missing plate file degrades to a text-only page in the export, never a broken book
- Image pages (schema v6, story_pages.image_media_type + image_prompt; files in database/images/pages/<page-id>.<ext> keyed by the page id so renumbering never orphans them): "Add as page" in the scene viewer POSTs the just-painted base64 to POST /api/stories/:id/pages/:n/image-page which inserts an empty-content plate row after page N (later pages bumped one-by-one DESC — the UNIQUE(story_id, page_number) constraint bites on bulk UPDATEs), stores bytes via imageStore('page'), carries prompt+cost_usd for accounting/alt text, and invalidates the preview (live write: client discardSpeculative() too). Client then re-fetches pages and turns to the new page; both modals close; failure keeps them open with a floating error. Plates render as .scene-plate <img> (GET /api/stories/:id/pages/:n/image); read-aloud/auto/scene-image/retry gray out on them (no prose) but writing continues past a plate as the last page; prompt.js renders plates as "[an inserted illustration (painted from: …)]" in generation context. Page delete / truncate-after / story delete all unlink plate files (never leave orphans); json body limit is 12mb for the base64 payload
- Low-storage banner (GET /api/disk = statfsSync on imageDir → {free_bytes,total_bytes}, nulls on failure): #diskBanner under the nav shows on EVERY section when free < 1GB or < 5% of the volume (< 250MB escalates to "almost full"), re-checked every 30s and right after each plate binding; hidden on nulls/server-down, keeps last state on error. Jest drives updateDiskBanner/checkDiskSpace directly — initDiskBanner skips its setInterval under JEST_WORKER_ID so tests hold no timers. NOTE: e2e/tests/app.e2e.test.js had a PRE-EXISTING stray `});` at old line 179 that closed its test.describe early (later tests ran as top-level tests, so Playwright never complained); fixed 2026-08-30 — new tests must live INSIDE the describe
- Audiobooks (schema v7, audiobooks TABLE keyed story_id, bytes at database/audio/<story-id>.mp3 + .mp3.tmp during jobs): whole-tale mp3 read by ONE GLOBAL sequential queue (decided: no parallelism on low-end devices; audiobookCurrent/audiobookQueue/audiobookCancel in app.js). Job narrates text pages in order (image pages skipped), reuses the narrationCache keyed sha256(text)+model+voice (unchanged pages free — cache hits make the job fully synchronous, finishing before the 201 lands), appends via writeAll to the tmp file, renames on done; costs from fetchGenerationCost per segment (best-effort), duration = words/2.5. Cancel checks between pages AND after collecting a page's streams (mid-page). POST validates against the speech catalogue and REJECTS pcm narrators (catalogue entries carry pcm:/gemini/i since 2026-08-30) — audiobooks are mp3-only by design. GET row gains stale (fingerprint = sha256(model+voice+page ids+contents) mismatch), queue_position (0 = reading now), file_missing grace. Boot marks pending rows failed ('Interrupted…'). Story delete cancels+unlinks; DELETE /api/stories/:id/audiobook removes row+file. Frontend: #audiobookBtn beside Export opens a modal (narrator verdict + estimates = pages/words math shared with Settings labels: 150 wpm, ~6KB/s mp3, chars×prompt_per_mchar + words×20×completion_per_mtok), explicit #audiobookStartBtn carrying the price (Create audiobook (≈$…); disabled when unusable/pending/empty, reason in text), then #audiobookBanner (write section, below pastPageBar): pending = text + progress bar + Stop; ready = Download link + Hide (MIDDLE-GROUND visibility: shows once per completed reading — localStorage st-ab-seen:<story>:<updated_at>, Hide marks it; pending always shows; failed shows error + retry). Cost ticked once per reading (chargedAudiobooks Set keyed story@updated_at) + checkDiskSpace on ready. Poll every 2s (skipped under JEST_WORKER_ID)
- Bookshelf (#bookshelfBtn nav → #bookshelfSection, GET /api/storage returns per-story {title, audiobook row+meta, plates:[{page_number,image_prompt,size_bytes}]}): download buttons are plain <a> to the audio/plate endpoints (plate route takes ?download=1 for Content-Disposition; audio always attaches). Deleting a plate = DELETE the image page (real page! renumbers following pages — confirm() warns; after delete the client reloads the shelf AND, if the story is open in Write, discardSpeculative+stopNarration+loadStoryPages so the reader sits on renumbered pages). Deleting an audiobook = DELETE /:id/audiobook (+refreshAudiobook if open)
- Narration (implemented per SCRIBETRIBE-STREAMING-TTS-IMPLEMENTATION.md, extended 2026-08-29): mp3 pass-through streaming (axios responseType:'stream' -> express pipe, upstream aborted via res.on('close')); pages are SEGMENTED at sentence boundaries (1800 chars; providers cap input — Deepgram 413s, Orpheus/Sesame 400 long text) and pieces stream back-to-back with bisect-retry on provider 400/413; pcm-only narrators (Gemini TTS) detected from the provider refusal and retried as pcm, delivered as one WAV (24kHz 16-bit mono header, not streamed); X-Generation-Id carries comma-joined segment ids; in-memory audio cache keyed sha256(text)+model+voice (replays never re-bill, entries ≤8MB); authoritative cost via GET /generation summed per id in /api/ai/generation-cost (server-cached per id); client bills once per joined id (Set guard); pages >16k chars → 413; CSP includes media-src 'self' blob:
- Speech catalogue (GET /api/speech-models) exposes TTS pricing {prompt_per_mchar, completion_per_mtok}; Settings narrator picker labels each model with ≈cost per page (chars = wordsPerPage×6.5, audio tokens ≈ words×20 — calibrated against a real Gemini bill), refreshed when words-per-page changes; Grok/MAI/Qwen/Kokoro/Voxtral take mp3 at page length, Gemini is slow (60s+/page) and priciest (~$0.12/page)
- Scene images (Grok Imagine Image 2.0 via OpenRouter's /images, backend/src/images.js): "Scene image" button condenses the page (POST image-prompt, tone-honoring) into an editable popup, then "Generate image" paints it (POST scene-image: 2:3, up to 3 cast portraits attached as identity references, MC→supporting→background, refs actually resolved on disk are reported). RENDERABLE-BY-DESIGN + ANNOUNCE-AND-WAIT: every image tone instruction composes moderation-passable prompts (even 18+ implies via shadow/drapery/aftermath — the image model refuses explicit content wholesale); on a provider 400 the server does NOT repaint — it rewrites the prompt aggressively safe (feeding the upstream reason into the rewrite: "ZERO nudity / ZERO gore", keep place/mood/composition/identity) and returns {refused:true, reason, sanitized_prompt, rewrite_cost_usd}; the client announces, repopulates the textbox, and waits for a fresh Generate press. LIVE-VERIFIED escalation: the CAST PORTRAITS can be the offenders (forced-nudity stories paint nude portraits; img2img calls with them 400 no matter how clean the text) — after a SECOND consecutive refusal the client sets dropSceneReferences, announces it, and the next press sends drop_references:true (server omits input_references); success or re-condense resets. Refusals cost nothing upstream (all-or-nothing billing); the rewrite LLM call is billed and reported via rewrite_cost_usd. Render variant selectable in the modal: low_1k (default, ≈$0.04) or medium_2k (≈$0.08), persisted in settings.sceneRenderQuality. Narrate/auto/scene-image buttons gray out with no story/page and while generating; auto button is ▶, stop is ■ (aria-labels carry the meaning). The painting opens in a zoomable/pannable viewer popup (wheel/pinch zoom, drag pan, dblclick toggles 2.5x↔full with pan reset; ghost Save downloads + Close). CSP: img-src includes data: for the viewer (a data: image under img-src 'self' alone shows a broken icon while everything else works); errors raised while ANY modal is open float above it (z-300 toast, .message--floating). Characters & worlds get background reference portraits (auto-enqueue on create; boot backfill of pre-feature rows; POST /:id/image to redo; sequential in-process queue; auto-enqueue is SILENCED in Jest unless ENABLE_BACKGROUND_IMAGES=1 so it never steals mocked axios calls). Character prompts: single figure, plain background, moderation-safe, medium/1K ($0.06); world prompts: strictly no people/creatures/action, low/1K ($0.04). Files live in database/images/<characters|worlds>/<id>.<ext> (gitignored), served via GET /:id/image; statuses/costs in image_status/image_cost_usd/image_updated_at columns (schema v4). Costs: char/world images tick SESSION only, once per generation (client Set keyed kind/id@updated_at); scene images tick session+story. Frontend polls lists every 4s while any image is pending. Image billing is all-or-nothing upstream; generateImage wraps axios errors with upstream status (4xx pass through for the refusal-retry logic)
- Entity editors (click a card; its buttons keep their own jobs): plain fields, NO AI assists; character sheet + image_prompt (editable blurb sent to the image generator, empty = auto-composed; honored by the redo queue); world name/genre/setting/lore + image_prompt. World LOREBOOK (schema v5, lore column, max 20k) is deliberately OUT of the creation form; it is honored by page generation (buildPrompt LOREBOOK block), scene-image condensing, and world image prompts (places only, still unpopulated). WORLDS ARE CANONICAL: stories reference the live world row, so edits (incl. lore) affect future page generation — by design the user decides when world-changing events persist; characters, by contrast, are copied into story cast state at creation. "Save & redo image" in the editors PUTs first, then POSTs the redo. Legacy grace: ready status with a missing file serves 404 ('Image file is missing'), the card <img> degrades to a failed placeholder (redo offered), and scene-image skips such refs silently


## Modular architecture (2026-08-30 restructure — shipped as v3.0.0)

- BACKEND: src/app.js is a COMPOSER (middleware, one runtime/service set, router mounting, static, error middleware, app.locals.dispose). All domain behavior lives in src/modules/: catalog (worlds/characters CRUD + generate_image field), stories (store SQL + cast.js contract), writing (service + routes for drafts/generate/regenerate/preview), imagery (service + the ONE sequential entity queue), audio (narration cache/segmentation + the ONE sequential audiobook queue + routes), library (storage aggregation + EPUB), auth (disabled adapter only). Shared bounded helpers in src/core/{http,validation}.js. Every route path and response shape is unchanged; createApp(db, {staticDir, imageDir, audioDir, logger}) is the test seam (logger injectable for asserting expected failures without stderr noise). Additive API field: generate_image:boolean on world/character create (omitted/true = paint, old-client compatible; false = create without image — backend/tests/images.test.js characterizes it).
- FRONTEND: native ES modules under app/ — no build step, <script type="module" src="app/bootstrap.js">. bootstrap.js builds ONE context ({api, state, notify, dialogs, shell, router, features}); features receive dependencies by argument, reach each other through the features registry (never cross-imports). core/router.js = hash routes (#/home, #/write, #/write/:storyId[/page/:n], #/library/stories|bookshelf, #/worlds, #/characters, #/settings); invalid hash recovers to #/home, unknown story id recovers to #/library/stories with an honest message; page turns use history.replaceState (no history spam); leaving Write stops narration. core/state.js = the small shared store (collections, reader position, settings, cost ledger, models caches; applySettings re-render hooks). core/dialogs.js = the ONE dialog manager (focus trap, opener restore, scroll lock, dirty guard, confirmDestructive/confirmPaid builders — burn/audiobook sliders and ALL native confirm() are gone). CSS split by ownership: styles/{tokens,base,shell,components}.css + styles/features/*; semantic state tokens (--state-prepared/queued/stale/refused/danger, --surface-manuscript/archive) live in tokens.css.
- NAV SHELL: destinations are Home, Write, Library (visible Stories/Bookshelf tabs, #libraryStoriesTab/#libraryBookshelfTab, route-backed), Worlds, Characters, Settings (utility). Nav carries aria-current="page". Home (app/features/home.js) = hero + Continue {latest story} + 3 recent manuscripts + scriptorium path. Catalogs are COLLECTION-FIRST: creation forms hide behind New world / New character (#worldNewBtn/#characterNewBtn toggles #worldCreateWrap/#characterCreateWrap); cards are keyboard-focusable with explicit Edit + More menu (regenerate with ≈cost, delete) — card-body click merely mirrors Edit.
- AGE GATE IS GONE: replaced by a contextual explicit-tone acknowledgement (first selection of the explicit tone in the story form, localStorage st-tone-explicit-ok) — no global first-visit gate.
- AUTH SEAM: app/features/auth/{adapter,gate}.js — disabled adapter only (mode 'disabled', status() → {state:'disabled'}, subscribe never fires); gate.canRender() always true (even on adapter error — a local app must not lock itself out). Dormant first-password/unlock TEMPLATES contain no inputs and are never mounted; no /api/auth endpoints exist. Security remains deferred by design.
- WRITE DESK: controls grouped (page nav / reading-media / composer / story management); narrationAutoBtn is labelled "Auto-read" (no glyph-only buttons); prepared-page state is explicit (#preparedNote: "Next page prepared…" / "…discards it"); primary button reads "Write next page" / "Use prepared page"; Ctrl/Cmd+Enter submits the composer; [ / ] turn pages when focus is outside form controls; #storyContextMode summarizes world + cast shape.
- BRAND ASSETS: frontend/brand/ holds the three art-directed hero WebPs + vesper/cinder/moth WebPs (PNG masters stay in ScribeTribe-UX-Architecture-OpenCode-2026-08-30/assets/generated/, never in production). moth-archive.webp = Bookshelf/lore empty states; cinder-cast.webp = cast-shape intro in story creation (never behind fields); vesper-threshold.webp = dormant future auth surfaces only.
- READ-only earlier pages; delete-later-pages and all destructive flows go through confirmDestructive with exact counts; deleteCurrentPage distinguishes plates.
